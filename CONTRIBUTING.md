# Como contribuir? 🤝

Obrigado por querer ajudar! Este é um projeto open source e toda contribuição é bem-vinda, de um link corrigido a um desafio novo. Este documento explica como participar e quais padrões seguimos para manter tudo organizado.

## Formas de contribuir

- **Reportar problemas:** link do Figma quebrado, erro de digitação, informação desatualizada.
- **Sugerir novos desafios:** abra uma issue com o nome do desafio, uma breve descrição e o link público do layout no Figma.
- **Melhorar a documentação:** README, este guia ou qualquer outro texto do repositório.
- **Enviar pull requests:** correções e novos desafios direto no código.

Em caso de dúvidas, [abra uma issue](https://github.com/iuricode/desafios-frontend/issues/new).

## Passo a passo

1. Faça um fork deste repositório.
2. Clone o seu fork e crie uma branch descrevendo a mudança:

   ```bash
   git checkout -b docs/corrige-link-desafio-12
   ```

3. Faça as alterações.
4. Envie seus commits em português (veja [padrão de commits](#padrão-de-commits)).
5. Faça o push da branch e abra um pull request com um pequeno resumo do que foi alterado e por quê.

## Adicionando um novo desafio

1. Use o próximo número da sequência na tabela do [README](README.md).
2. Adicione uma linha com o número, o nome do desafio e o link do layout no Figma.
3. Confira se o link abre sem pedir login ou permissão de acesso.

## Padrão de commits

Para uma melhor semântica nos commits, recomendamos nosso repositório sobre [padrões de commits](https://github.com/iuricode/padroes-de-commits). Ele facilita a revisão do seu pull request. Exemplo:

```
📚 docs: corrige link do desafio 12
```

## Código de conduta

Seja respeitoso(a) com quem participa do projeto. Críticas são bem-vindas quando forem construtivas e focadas no conteúdo, nunca nas pessoas.
